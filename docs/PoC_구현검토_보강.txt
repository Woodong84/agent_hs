### 핵심 구현 내용

이번 PoC 단계에서 실제 코드로 구현된 핵심 기능들을 **동작 원리**와 **사용 기술** 중심으로 상세히 기술합니다.

**1.1 에이전트 워크플로우 (Agent Workflow)**

* **구현 기능:**
  반도체 품목 정보를 입력받아 HS-Code를 자동 추천하는 ReAct 오케스트레이터 에이전트

* **동작 원리:**
  사용자가 품목명·재질·용도·수출입 방향을 입력하면 에이전트가 다음 순서로 처리합니다.
  (1) 입력값을 구조화된 질문으로 변환 후 에이전트에 전달
  (2) ReAct(Reasoning + Acting) 루프에서 어떤 도구를 어떤 순서로 호출할지 자율 판단
  (3) search_hs_code_rag → query_tax_rate 순으로 도구 호출
  (4) RAG 검색 결과가 임계값 미만이면 LLM 지식 기반 Fallback으로 자동 전환
  (5) 최종 HS-Code 추천 + 세율 정보를 통합하여 사용자에게 반환

* **주요 기술:**
  (1) LangChain
  - create_react_agent : LLM이 ReAct(Reasoning and Acting), 즉 '추론'과 '행동'을 결합하여 문제를 해결하도록 설정된 에이전트 객체를 생성하는 함수
  - AgentExecutor : create_react_agent로 만든 에이전트 두뇌와 실제 실행할 도구들을 결합하여 구동시키는 런타임 환경
  (2) LLM
  - Azure OpenAI gpt-4.1 (메인) : 에이전트의 주력 두뇌로 사용
  - Fallback Claude Sonnet 4.5 (대체) : 메인 모델 예외 발생 시 즉각 요청을 이어받아 처리하는 백업 모델
  (3) PromptTemplate (ReAct 형식)
  - LLM이 환각(Hallucination)에 빠지지 않고, 정해진 도구를 논리적인 순서대로 사용하도록 통제하는 가이드라인
  (4) Pydantic-Settings 기반 환경 설정
  - DB 접속 정보, API 키, 모델 버전, 유사도 임계값 등 시스템 구동에 필요한 환경 변수들을 Pydantic 라이브러리를 통해 관리

**1.2 도구(Tool) 및 함수 연동**

* **구현 기능:**
  (1) HS-Code RAG 검색 도구 (search_hs_code_rag)
  (2) 관세율 조회 도구 (query_tax_rate)

* **동작 원리:**
  (1) HS-Code RAG 검색 도구 (search_hs_code_rag)
  - LLM이 품목명·재질·용도를 JSON 형태의 Action Input으로 도구에 전달
  - 입력값을 단일 쿼리 문자열로 결합 후 Pinecone에서 코사인 유사도 검색 (top-k=5)
  - 유사도 최댓값이 임계값(기본 0.30) 이상인 경우에만 후보 HS-Code와 근거 문서 반환
  - 동일 HS-Code를 지지하는 청크가 여러 개인 경우 합산하여 신뢰도 산정
  - 상위 3개 류(類) 코드가 서로 다를 경우 충돌 플래그(TYPE-1/2/3) 자동 생성
  (2) 관세율 조회 도구 (query_tax_rate)
  - HS-Code 앞 2자리(류)를 키로 정적 세율 테이블에서 기본관세율 조회
  - 한-미·한-EU·한-중 FTA 협정 세율 및 수입 요건 반환
  - 실제 운영 시 관세청 UNI-PASS API 연동으로 대체 가능한 구조로 설계

* **주요 기술:**
  (1) LangChain @tool 데코레이터
  - 파이썬 함수를 LLM 에이전트가 인식하고 호출할 수 있는 도구(Tool)로 변환
  (2) Pydantic 자동 스키마 생성
  - LLM이 내뱉는 결과물의 포맷을 강제 적용
  (3) JSON 방어적 파싱 (LLM 오형식 대응)
  - LLM이 전체 입력을 product_name 단일 필드에 JSON 문자열로 직렬화하는 오형식 발생 시, 자동 파싱하여 각 필드로 분해하는 방어 로직 내장
  (4) 관세율 Fallback 정적 테이블
  - UNI-PASS API 호출 실패 시 내부 정적 테이블(류 38, 39, 84, 85, 76, 90)에서 즉시 반환

**1.3 데이터 및 메모리 (RAG & Context)**

* **구현 기능:**
  반도체 HS-Code 참조 문서(TXT/PDF) 기반 검색 증강 생성(RAG)

* **동작 원리:**
  문서 적재: data/raw/ 폴더의 TXT/PDF 파일을 로드 — TXT는 --- 구분자 기반 메타데이터(HS-Code·문서명·발행연도·류) 파싱, PDF는 PyPDFLoader로 페이지별 로드
  청킹: RecursiveCharacterTextSplitter로 chunk_size=500 / overlap=50으로 분할 후 각 청크에 chunk_id 부여
  임베딩: Azure OpenAI text-embedding-3-small (1,536차원)으로 청크 벡터화
  저장: Pinecone 인덱스(hs-code-docs, cosine metric)에 배치 50개 단위로 업로드
  검색: 사용자 쿼리를 동일 임베딩 모델로 변환 후 similarity_search_with_score로 top-5 청크 반환
  근거 품질 채점: 문서명·페이지·인용 문장·유사도를 기준으로 8점 만점 자동 채점

* **주요 기술:**
  Pinecone Serverless (cloud vector DB)
  langchain-pinecone 0.2.0
  Azure OpenAI text-embedding-3-small (1536차원)
  RecursiveCharacterTextSplitter (chunk=500, overlap=50)
  similarity_search_with_score (cosine)

**[신설] 1.3.2 근거 품질 채점 기준 (8점 만점 상세)**

  근거 품질 점수(evidence_quality_score)는 _score_evidence() 함수에서 자동 산출됩니다.
  Top-1 후보의 첫 번째 증거(evidence[0])를 기준으로 아래 항목별 가산:

  | 채점 항목                    | 조건                         | 점수    |
  |-----------------------------|------------------------------|--------|
  | 증거 존재                   | evidence 리스트가 1개 이상     | +2.0점  |
  | 문서명 포함                  | doc_name 필드가 비어있지 않음   | +1.5점  |
  | 페이지 정보 포함             | page 필드가 비어있지 않음       | +1.0점  |
  | 인용 문장 충분               | citation 길이 > 20자          | +1.5점  |
  | 유사도 높음 (고신뢰)          | similarity_score ≥ 0.85      | +2.0점  |
  | 유사도 보통 (중신뢰)          | similarity_score ≥ 0.75      | +1.0점  |
  | **최대 합산**                |                              | **8.0점** |

  FOUP 시나리오 채점 예시 (실제 결과):
    - 증거 존재: +2.0 (hs_3923_FOUP.txt 청크 반환됨)
    - 문서명 포함: +1.5 (doc_name = "hs_3923_FOUP.txt")
    - 페이지 포함: +1.0 (page = "p.1")
    - 인용 문장: +1.5 (citation 120자 반환)
    - 유사도 0.47 → 0.75 미달: +0.0
    - 합계: 6.0/8.0점 ← UI 표시값과 일치

**[신설] 1.3.3 재현 절차**

  로컬 환경에서 전체 시스템을 재현하는 최소 절차입니다.

  사전 요건:
    - Python 3.11
    - .env 파일에 아래 키 설정:
        AZURE_OPENAI_API_KEY=...
        AZURE_OPENAI_ENDPOINT=...
        PINECONE_API_KEY=...
        PINECONE_INDEX_NAME=hs-code-docs

  재현 단계:
    1. 의존성 설치
       pip install -r requirements.txt

    2. Pinecone 문서 적재 (최초 1회)
       python data_ingest/ingest.py
       → "적재 완료" 메시지 및 벡터 수 확인

    3. Streamlit UI 실행
       streamlit run app.py
       → 브라우저에서 localhost:8501 접속

    4. 시나리오 1 재현 (RAG 정상 추천)
       품목명: FOUP
       재질: 폴리카보네이트
       용도: 300mm 웨이퍼 클린룸 이송
       수출입: 수입
       유사도 임계값: 0.30
       → 기대 결과: Fallback=아니오, Top-1 = 3923100000, 근거 품질 ≥ 5.0

    5. 시나리오 2 재현 (Fallback 전환)
       품목명: 양자컴퓨터 희석냉동기
       재질: 알루미늄, 구리
       용도: 큐비트 냉각
       유사도 임계값: 0.45
       → 기대 결과: Fallback=예, 근거 품질 0.0, 경고 배너 표시

**[신설] 1.5 응답 상태별 정책 (Confidence / Conflict / Fallback)**

  시스템은 RAG 검색 결과의 품질에 따라 3가지 상태를 구분하여 각기 다른 응답을 사용자에게 전달합니다.

  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ 상태 A: RAG 근거 존재 + 후보 간 충돌 (Conflict)                             │
  └─────────────────────────────────────────────────────────────────────────────┘

  조건:
    - fallback = False (유사도 임계값 통과)
    - conflict_flag = True
    - TYPE-1: 상위 3개 후보의 류(2자리) 코드가 2종류 이상
    - TYPE-2: 기존 HS-Code(사용자 입력)와 Top-1 추천 코드의 앞 6자리 불일치
    - TYPE-3: 복수의 HS-Code가 각각 2개 이상의 청크로 지지되어 동등하게 경쟁

  사용자 응답 정책:
    - UI에 주황색 경고 배너 표시:
        "⚠️ 분류 충돌 감지 — TYPE-X: [충돌 유형 설명] / [충돌 상세 내용]"
    - HS-Code 후보는 정상 표시 (최대 3순위까지)
    - 근거 품질 점수 정상 산출 및 표시
    - 감사 로그에 conflict_flag=true, conflict_type, conflict_detail 기록

  처리 예시:
    FOUP(3923류)와 반도체 장비(8486류) 후보가 동시에 상위에 오를 경우:
    → "⚠️ 분류 충돌 감지 — TYPE-1: 상위 후보 간 류(類) 코드 충돌 / 류 충돌: 39, 84"
    → 사용자가 직접 1순위를 확인·선택 후 감사 로그에 수정 사유 입력 권고

  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ 상태 B: RAG 근거 약함 → LLM Fallback 전환 (Fallback)                        │
  └─────────────────────────────────────────────────────────────────────────────┘

  조건:
    - fallback = True
    - fallback_reason 중 하나:
        · "PINECONE_API_KEY 미설정"   — 환경변수 누락
        · "Pinecone 연결 실패: ..."  — 네트워크/인증 오류
        · "RAG 검색 실패: ..."       — 쿼리 실행 오류
        · "검색 결과 없음 (문서 미적재)" — 인덱스 비어있음
        · "유사도 N.NN < 임계값 N.NN"  — 유사도 미달 (가장 빈번)

  사용자 응답 정책:
    - UI에 노란색 경고 박스 표시:
        "⚠️ RAG 근거 없음: [fallback_reason] — LLM 지식 기반 추천이 제공됩니다."
    - LLM이 자체 지식으로 HS-Code를 추천하되, 추천 텍스트에 "반드시 전문가 확인 필요" 문구 포함
    - 근거 품질 점수 = 0.0/8.0으로 고정 표시
    - Fallback=예 레이블 표시
    - 감사 로그에 fallback=true, fallback_reason 기록

  처리 예시:
    양자컴퓨터 희석냉동기 입력, 유사도 0.18 < 임계값 0.30:
    → "⚠️ RAG 근거 없음: 유사도 0.18 < 임계값 0.30 — LLM 지식 기반 추천"
    → "* RAG 문서 근거 없음 — LLM 지식 기반 추천. [1순위] HS-Code 8419899090..."
    → 근거 품질 0.0/8.0, Fallback=예

  ┌─────────────────────────────────────────────────────────────────────────────┐
  │ 정상 상태: RAG 근거 존재 + 충돌 없음 (High Confidence)                       │
  └─────────────────────────────────────────────────────────────────────────────┘

  조건:
    - fallback = False, conflict_flag = False
    - Top-1 유사도 ≥ similarity_threshold

  사용자 응답 정책:
    - 경고 없이 HS-Code 후보 및 근거 정상 표시
    - 신뢰도 레이블: "높음"(≥0.60) / "중간"(≥0.45) / "낮음"(<0.45)
    - 근거 품질 점수 정상 산출 (최대 8.0점)
