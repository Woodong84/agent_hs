# E2E 서비스 개발

## 1. 최종 아키텍처 요약

- **완성된 아키텍처 핵심:** Pinecone RAG + LangChain ReAct 기반 단일 오케스트레이터 에이전트 구조 완성. Azure OpenAI gpt-4.1(LLM) + text-embedding-3-small(임베딩) + Pinecone Serverless(벡터 DB, 246개 문서 약 6,000벡터 적재) + 정적 세율 테이블(9개 류) 파이프라인을 Render 클라우드에 배포하여 서비스 운영 중.

- **최종 산출물 형태:** Streamlit 웹앱 형태의 반도체 수출입 담당자용 HS-Code 자동 추천 에이전트. 품목 정보 입력 → HS-Code Top-3 추천 + 근거 문서 출처 + 세율 정보 + 충돌 경고를 단일 화면에서 제공. 담당자의 최종 선택 및 감사 로그 자동 저장 기능 포함.

- **Agent 구조:**

```
사용자 입력 (Streamlit UI)
        │
        ▼
Orchestrator — ReAct AgentExecutor (gpt-4.1)
        │
        ├─► search_hs_code_rag   → Pinecone 코사인 유사도 검색 (top-5)
        │         └─ 충돌 감지 (TYPE-1/2/3) + 후보 Top-3 생성
        │
        ├─► query_tax_rate        → 정적 세율 테이블 (28/38/39/69/76/84/85/90류)
        │
        └─► save_audit_log       → 코드 직접 호출 (LLM 경유 X)
                  └─ logs/audit_log.json (JSONL 누적 저장)
```

## 3. 창출된 핵심 가치

### 3-1. 비즈니스 가치

- 건당 60분 이상 소요되던 HS-Code 조회를 10초 이내 1차 답변으로 단축 → 담당자가 5분 내 최종 확정 판단 가능
- 충돌 감지(TYPE-1/2/3) 및 A/B 비교표 자동 제공으로 사내 코드 불일치 상황을 즉시 인지하고 정리 가능
- 감사 로그(입력값·추천 결과·담당자 선택·수정 사유·응답시간) 자동 기록으로 관세 감사 대응 소명 자료 생성 자동화

### 3-2. 기술적 가치

- 단순 키워드 검색이 아닌 RAG + ReAct 기반 Actionable Agent 구조 구현 — 도구 선택·순서·Fallback 전환을 에이전트가 자율 판단
- Pinecone Serverless + Render 클라우드 조합으로 로컬 환경 의존 없는 완전 클라우드 개발·배포 파이프라인 확보
- 유사도 임계값 게이팅·면책 문구 강제 삽입·감사 로그 직접 호출 등 규제 도메인 특화 가드레일 설계 경험 확보

## 4. 운영 및 보안 고려 사항

- **인증 방식:** Azure OpenAI·Pinecone API 키를 Render 대시보드 Environment 탭에 암호화 저장. 코드 내 하드코딩 없이 Pydantic-Settings로 환경변수만 참조. `.env.example` 제공으로 로컬 개발 시에도 키 노출 방지.

- **권한 통제:** Pinecone 인덱스는 검색(Read) API만 서비스에 노출. 문서 적재(Ingest·Write)는 별도 실행 경로(`data_ingest/ingest.py` 또는 UI 적재 버튼)로 분리. 감사 로그(`audit_log.json`)는 JSONL 누적 방식으로 수정·삭제 없이 append only 구조 유지.

- **입력값 방어:** LLM이 도구 호출 시 전체 입력을 `product_name` 단일 필드에 JSON 문자열로 직렬화하는 오형식(Malformed Tool Call) 발생에 대비한 방어 파싱 로직 내장. 유사도 임계값 하한선(0.30) 코드 강제 적용으로 슬라이더 악용 시에도 최소 품질 관문 유지.

- **장애 대응:** Azure OpenAI 미설정 시 Claude Sonnet 4.5로 LLM 자동 Fallback. Pinecone 연결 실패 시 `fallback=True` 반환 + 오류 원인 메시지 UI 표시. 세율 API 미연동 시 내부 정적 테이블(9개 류)에서 즉시 반환하여 서비스 중단 없이 처리.

## 5. 회고 및 향후 확장

### 기술적 한계

- 응답 시간 7~15초로 목표(10초 이내) 경계선 — LLM 3회 왕복 구조 및 스트리밍 미적용으로 결과가 완성될 때까지 UI가 빈 화면으로 유지되어 체감 대기 시간이 실제보다 길게 느껴짐
- Clarification 2턴 대화 흐름 미완성 — 충돌 감지(TYPE-1) 후 경고 배너·A/B 비교표 표시까지 구현, 에이전트가 직접 추가 질문을 주고받아 단일 코드로 수렴하는 대화 루프 미구현
- 관세청 UNI-PASS API 미연동 — 정적 세율 테이블 9개 류만 커버, 신규 품목·특수 세율 실시간 조회 불가
- 정량 평가셋 미구축 — 수동 3건 테스트로 Top-3 Hit Rate 목표(≥70%) 공식 측정 불가

### Next Step

- **스트리밍 응답 적용** (`st.write_stream` + `astream_events`) — 토큰 단위 점진적 출력으로 체감 대기 시간 단축
- **Clarification 2턴 대화 완성** — TYPE-1 충돌 시 에이전트 질문 → 사용자 답변 → 단일 코드 수렴 루프 구현 (LangGraph 전환 또는 대화 메모리 연동)
- **UNI-PASS API 실시간 연동** — 정적 세율 테이블을 관세청 Open API 실시간 조회로 대체
- **평가셋 30건 구축 및 Hit Rate 정량 측정** — 반도체 대표 품목 30건 Ground Truth 구축 후 Top-1/Top-3 정확도 공식 측정
- **로그 기반 도메인 특화 튜닝** — 누적 감사 로그에서 오분류 케이스 추출 → RAG 문서 보강 및 프롬프트 개선 반복
