# 최종 산출물 — HSAgent HS-Code 추천 AI

---

## 1. 프로젝트 개요

### 프로젝트명
대외 무역관리 지원 AI Agent 구현 — 반도체 수출입 HS-Code 자동 추천 시스템 (HSAgent)

### 무엇을 만들었나

반도체 수출입 담당자가 품목명·재질·용도를 입력하면, AI가 관련 관세 문서를 검색해 적합한 HS-Code를 근거와 함께 추천해 주는 웹 서비스입니다.

기존에는 담당자가 관세청 사례집을 수동으로 검색하거나 관세사에 문의해 결과를 받는 데 **건당 60분 이상**이 걸렸습니다. 이 서비스를 통해 **10초 이내에 1차 판단 근거**를 제공하고, 담당자가 5분 안에 최종 결정을 내릴 수 있도록 지원하는 것이 목표였습니다.

### 기술 스택

| 구분 | 기술 |
|---|---|
| LLM (주 모델) | Azure OpenAI gpt-4.1 |
| LLM (백업 모델) | Claude Sonnet 4.5 |
| 임베딩 | text-embedding-3-small (1,536차원) |
| 벡터 DB | Pinecone Serverless |
| 에이전트 프레임워크 | LangChain ReAct |
| UI | Streamlit |
| 배포 | Render (클라우드) |

### 기대 효과
- 수작업 문서 탐색 시간 단축
- 관세청 근거 문서 기반 분류로 오류 위험 감소
- 코드 선택 이력을 자동 기록해 감사 대응 시 소명 자료 즉시 제공

## 2. 서비스 아키텍처

### 전체 흐름

```
사용자 입력 (Streamlit 웹 UI)
        │  품목명 / 재질 / 용도 / 수출입 방향
        ▼
Orchestrator — ReAct 에이전트 (gpt-4.1)
        │
        ├─► search_hs_code_rag   → Pinecone 유사도 검색 (상위 5개 문서)
        │         └─ HS-Code 후보 Top-3 생성 + 충돌 감지
        │
        ├─► query_tax_rate        → 세율 테이블 조회
        │         └─ 기본관세율 + 한-미·EU·중 FTA 협정세율
        │
        └─► save_audit_log       → 감사 로그 자동 저장
                  └─ logs/audit_log.json (누적 기록)
```

### 주요 구성 요소

**① RAG 검색 (문서 기반 근거 탐색)**
- 반도체 관련 관세청 품목분류 사례집, HS 표준 해석 지침 등 246개 문서를 Pinecone에 적재
- 사용자 입력을 벡터로 변환해 가장 유사한 문서 청크 5개를 코사인 유사도로 검색
- 유사도가 기준값(기본 0.45) 미만이면 "문서 근거 없음(Fallback)" 상태로 전환

**② 충돌 감지 (Conflict Detection)**
- 검색 결과에서 서로 다른 HS 분류 류(類)가 혼재할 때 자동으로 감지해 경고 표시

**③ 세율 조회**
- 반도체 주요 9개 류(28·38·39·69·76·84·85·90류) 세율 테이블 내장
- 향후 관세청 UNI-PASS API로 교체 가능한 구조로 설계

**④ 감사 로그**
- 입력값, 추천 결과, 담당자 선택, 응답 시간을 JSONL 형식으로 자동 기록
- 관세 감사 시 "왜 이 코드를 선택했는가"를 문서 수준으로 소명 가능

## 3. 핵심 기능 및 구현 내용

### 3-1. HS-Code 추천 (정상 케이스)

품목 정보를 입력하면 HS-Code 후보를 최대 3개까지 근거 문서와 함께 제시합니다.

**실제 테스트 예시 — FOUP(웨이퍼 이송 용기)**

| 항목 | 내용 |
|---|---|
| 입력 | 품목명: FOUP / 재질: 폴리카보네이트 / 용도: 300mm 웨이퍼 클린룸 이송 / 수출(미국) |
| 추천 결과 | **1순위 3923100000** — 플라스틱제 운반 용기 (신뢰도: 중간) |
| 근거 | 관세청 품목분류 사례집 — "플라스틱 재질 웨이퍼 캐리어는 3923호에 분류" |
| 세율 | 기본관세율 8% / 한-미 FTA 협정세율 **0%** |
| 근거 품질 | 6.0 / 8.0점 |

### 3-2. Fallback 처리 (문서 근거 없음)

관련 문서가 없는 품목은 AI 자체 지식만으로 추천하되, 반드시 경고 메시지와 함께 제공합니다.

**실제 테스트 예시 — 양자컴퓨터 희석냉동기**

- 검색 유사도 0.18 → 기준값(0.30) 미달 → Fallback 전환
- UI에 황색 경고 배너 출력: *"RAG 문서 근거 없음 — AI 지식 기반 추천. 반드시 전문가 확인 필요"*
- 모든 응답 하단에 면책 문구 고정 출력

### 3-3. 충돌 감지 및 경고 (Conflict Detection)

동일 품목에 대해 서로 다른 분류 기준이 충돌할 때 자동 감지하고 담당자에게 알립니다.

| 유형 | 상황 | 대응 |
|---|---|---|
| **TYPE-1** | 후보 코드들이 서로 다른 류(類)에 속함 | 추가 정보 확인 질문 유도 |
| **TYPE-2** | 기존 사용 코드와 추천 코드가 불일치 (예: 재질 변경) | A/B 비교표 + "사내 코드 통일 검토 필요" 경고 |
| **TYPE-3** | 여러 근거 문서가 서로 다른 코드를 지지 | 관세사 확인 강권 |

**실제 테스트 예시 — CMP Slurry (화학기계적 연마재)**

- 기존 사내 코드 3824.99 ↔ RAG 추천 3810100000 불일치 → TYPE-2 감지
- A/B 비교 카드 자동 출력, "사내 코드 통일 검토 필요" 주황 배너 표시
- 기본관세율 6.5% / 한-중 FTA 확인 필요 안내

### 3-4. 세율 조회 및 감사 로그

- 수출·수입 방향과 대상국에 따라 기본관세율과 FTA 협정세율을 자동 조회
- 담당자의 최종 HS-Code 선택과 수정 사유를 포함해 전체 이력을 자동 저장

## 5. 기술 문제 해결 과정

### 문제 1 — RAG가 항상 Fallback으로 빠지는 현상

**상황:** 슬라이더에서 유사도 임계값을 설정해도 에이전트가 항상 "문서 없음"으로 처리

**원인:** UI 슬라이더 값이 에이전트 도구 호출 시 전달되지 않고, 코드 내 기본값 0.75가 고정 적용됨. Pinecone 실제 유사도 범위(0.37~0.55)와 비교해 기준이 너무 높아 모든 결과가 미달 처리

**해결:** 입력 질문 구성 함수에 임계값을 명시적으로 포함시키고, 기본값을 0.75 → 0.30으로 조정. UI 슬라이더 기본값은 0.45로 설정

**결과:** FOUP 테스트 기준 Fallback=아니오, 근거 품질 6.0/8.0점 달성

---

### 문제 2 — 신뢰도가 항상 "낮음"으로 표시

**상황:** 유사한 문서가 잘 검색되어도 신뢰도가 항상 "낮음"으로 출력

**원인:** 신뢰도 기준값(높음≥0.85, 중간≥0.75)이 Pinecone 실측 유사도 범위(0.37~0.55)보다 훨씬 높게 설정되어 있었음

**해결:** 실측 범위에 맞게 기준 재조정 — 높음≥0.60 / 중간≥0.45

**결과:** 실제 검색 품질을 반영한 신뢰도 표시로 개선

---

### 문제 3 — 감사 로그에 입력값이 빈칸으로 저장

**상황:** 감사 로그를 확인하면 입력한 품목명·재질·용도가 모두 `{}` 빈 값으로 기록됨

**원인:** 감사 로그 저장 기능을 AI 에이전트의 도구 목록에 포함시켰더니, AI가 도구를 호출할 때 초기 입력값을 참조하지 못하고 빈 값을 전달

**해결:** 감사 로그 저장 기능을 AI 도구 목록에서 제거하고, 에이전트 실행 완료 후 코드에서 직접 저장하도록 변경

**결과:** 입력값·추천 결과·응답시간 전체가 정상 기록됨

---

### 문제 4 — Pinecone 벡터 중복 누적 (21,301개 → 정상화)

**상황:** 정상 벡터 수는 약 6,000개인데, 실제로는 21,301개가 쌓여 있음

**원인:** 문서 적재 기능이 기존 데이터를 삭제하지 않고 계속 추가만 하여, 버튼을 여러 번 클릭할수록 중복 데이터가 누적

**해결:** 적재 전 기존 벡터를 전체 삭제하는 단계를 추가해 항상 최신 데이터만 유지

**결과:** 중복 제거로 검색 정확도 개선, 정상 벡터 수 유지

---

### 문제 5 — SC-001 테스트에서 FOUP 대신 STOCKER가 1순위로 출력

**상황:** FOUP를 입력했는데 관련 없는 "웨이퍼 보관용 물류창고 STOCKER"가 1순위로 추천됨

**원인:** 232개 표준 해석 문서가 검색을 지배하면서, STOCKER 문서의 "웨이퍼 이송·보관" 키워드가 FOUP와 유사도에서 오매칭

**해결:** ① 검색 쿼리에서 품목명을 2회 반복해 가중치 효과 부여, ② FOUP 문서에 영문명·유사 품목·관련 키워드를 추가해 검색 정확도 향상

**결과:** FOUP 입력 시 3923100000이 1순위로 정상 출력

---

### 문제 6 — 클라우드 기반 개발 환경 전환

**상황:** 회사 보안 정책으로 업무 PC에서 LLM 사용 불가, 개인 PC 성능도 부족

**해결:** GitHub(코드 관리) + Pinecone(벡터 DB) + Render(서비스 배포) 조합으로 완전한 클라우드 개발 환경 구축

**결과:** 장소와 장비에 관계없이 일관된 개발·운영 가능. 오히려 배포 자동화 측면에서 더 효율적인 환경 확보

## 6. 향후 개선 및 확장 방향

### 단기 개선 (1~3개월)

| 과제 | 내용 | 기대 효과 |
|---|---|---|
| 스트리밍 응답 적용 | 답변을 완성 후 한 번에 표시하는 방식 → 글자가 생성되는 대로 실시간 표시 | 체감 응답 시간 단축 |
| Clarification 2턴 구현 | 충돌 감지 시 에이전트가 추가 질문 → 사용자 답변 → 단일 코드로 수렴 | 분류 정확도 향상 |
| UNI-PASS API 연동 | 정적 세율 테이블을 관세청 실시간 API로 대체 | 최신 세율 자동 반영 |
| 평가셋 30건 구축 | 대표 품목 30건 정답 라벨 구축 후 자동 정확도 측정 | Hit Rate 정량화 |

### 장기 확장 (6개월 이상)

- **LangGraph 멀티 에이전트 전환** — 현재 단일 에이전트 구조를 역할별로 분리해 대화 흐름 안정성 강화 (Clarification 2턴 구현의 기술적 전제 조건)
- **로그 기반 자동 튜닝** — 쌓인 감사 로그에서 오분류 케이스를 추출해 문서 보강 및 프롬프트 개선 자동화
- **사내 시스템 연동** — SAP 자재 마스터, 기존 통관 시스템과 연동해 코드 자동 입력
- **도메인 확장** — 반도체 외 디스플레이, 배터리 등 하이테크 품목으로 적용 범위 확대
