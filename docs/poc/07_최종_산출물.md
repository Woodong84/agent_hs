# 프로젝트 개요

## 프로젝트명

대외 무역관리 지원 AI Agent 구현(HS-Code 추천) 프로젝트이다.\
반도체 수출입 품목의 HS-Code 탐색·분류 업무를 AI로 지원하는 것을 목표로 했다.

## 기술 스택

LLM : Azure OpenAI gpt-4.1, 임베딩 : text-embedding-3-small, 벡터DB : Pinecone Serverless, 프레임워크 : LangChain ReAct, UI : Streamlit, 배포 : Render를 사용하여, 최대한 어디서든 작업 환경에 구애를 덜 받아서 구현할 수 있도록 클라우드 환경으로 구성했다.\
(근무 환경 특성 상 한 곳에서, 하나의 PC에서 작업이 불가능했기 때문에)

## 주요 기능

자연어 입력 기반 HS-Code Top-3 추천, 근거 문서 인용, conflict 감지, 세율 정보 제공, 감사 로그 저장 기능을 구현했다.

## 기대 효과

수작업 문서 탐색 시간을 줄이고, 근거 기반 분류 판단과 감사 대응력을 높이며, 담당자의 최종 의사결정을 빠르게 지원하는 효과를 기대했다.


# 서비스 아키텍처

## 사용자 인터페이스

Streamlit 웹앱이 품목명, 재질, 용도 등 입력을 받아 결과를 시각적으로 제공한다.

## Orchestrator Agent

ReAct 기반 에이전트가 입력 해석, 도구 호출 순서 결정, fallback 및 면책 문구 포함 응답 생성을 담당한다.

## RAG 검색 컴포넌트

* 반도체 관련 관세청 품목분류 사례집 PDF문서, HS 표준 해석 지침 등 246개 문서를 Pinecone에 적재

* 사용자 입력을 벡터로 변환해 가장 유사한 문서 청크 5개를 코사인 유사도로 검색

* 유사도가 기준값(기본 0.45) 미만이면 "문서 근거 없음(Fallback)" 상태로 전환

## 세율 조회 컴포넌트

* 반도체 주요 9개 류(28·38·39·69·76·84·85·90류) 세율 테이블 내장

* 향후 실시간 조회 시 관세청 UNI-PASS API로 교체 가능한 구조로 설계

## 로그 및 운영

audit log를 JSONL 형태로 누적 저장해 추적성과 감사 대응성을 확보했다.

* 입력값, 추천 결과, 담당자 선택, 응답 시간을 JSONL 형식으로 자동 기록

* 관세 감사 시 "왜 이 코드를 선택했는가"를 문서 수준으로 소명 가능

## 핵심 데이터 흐름

1. 사용자가 Streamlit UI에 품목 정보를 입력한다.

2. Orchestrator가 입력을 분석하고 search_hs_code_rag를 호출한다.

3. Pinecone 검색 결과를 바탕으로 HS-Code 후보, 근거, conflict 여부를 정리한다.

4. 필요 시 query_tax_rate를 호출해 세율 정보를 결합한다.

5. 최종 추천 결과와 경고 메시지를 사용자에게 반환하고 audit log를 저장한다.

* 전체 흐름\
  사용자 입력 (Streamlit 웹 UI)\
  │ 품목명 / 재질 / 용도 / 수출입 방향\
  ▼\
  Orchestrator — ReAct 에이전트 (gpt-4.1)\
  │\
  ├─► search_hs_code_rag → Pinecone 유사도 검색 (상위 5개 문서)\
  │ └─ HS-Code 후보 Top-3 생성 + 충돌 감지\
  │\
  ├─► query_tax_rate → 세율 테이블 조회\
  │ └─ 기본관세율 + 한-미·EU·중 FTA 협정세율\
  │\
  └─► save_audit_log → 감사 로그 자동 저장\
  └─ logs/audit_log.json (누적 기록)



# 핵심 기능 및 Agent 구현 내용

## 사용 기술/라이브러리

* LangChain — ReAct 기반 AgentExecutor와 tool orchestration 구현

* Azure OpenAI gpt-4.1 — 메인 추론 모델

* Claude Sonnet 4.6 — 예외 상황용 fallback 모델

* text-embedding-3-small — 문서 임베딩 생성

* Pinecone Serverless — 벡터 검색 저장소

* Streamlit — 최종 사용자 웹앱 UI

* Render — 클라우드 배포 환경

### HS-Code 추천 Agent

품목 정보 입력을 받아 Pinecone top-k 검색을 수행하고 HS-Code 후보와 근거 문서를 함께 제시하도록 구현했다.

### Fallback 응답 처리

유사도 임계값 미달 시 문서 근거 부족 상태로 판단하고, LLM 기반 참고 답변과 경고 메시지를 분리해 반환하도록 설계했다.

* UI에 황색 경고 배너 출력: *"RAG 문서 근거 없음 — AI 지식 기반 추천. 반드시 전문가 확인 필요"*

* 모든 응답 하단에 면책 문구 고정 출력

### Conflict 감지 및 경고

후보 코드 간 류 분리, 내부 코드 불일치, 근거 문서 상충 상황을 conflict 유형으로 나누어 후속 처리 기준을 정의했다.\
**실제 테스트 예시 — CMP Slurry (화학기계적 연마재)**

* 기존 사내 코드 3824.99 ↔ RAG 추천 3810100000 불일치 → TYPE-2 감지

* A/B 비교 카드 자동 출력, "사내 코드 통일 검토 필요" 주황 배너 표시

* 기본관세율 6.5% / 한-중 FTA 확인 필요 안내

### 세율 조회 및 로그 저장

정적 세율 테이블 조회와 audit log 저장 기능을 연결해 결과 추적성과 실무 활용성을 높였다.

* 수출·수입 방향과 대상국에 따라 기본관세율과 FTA 협정세율을 자동 조회

* 담당자의 최종 HS-Code 선택과 수정 사유를 포함해 전체 이력을 자동 저장

[작성 가이드] 실행 로그, 모듈 구조, 실제 입출력 샘플이 추가되면 구현 완성도를 더 명확히 보여줄 수 있습니다.

# 기술 문제 해결 과정

### 클라우드 기반 개발 환경 전환

1. 문제 상황 — 회사 보안 정책과 개인 PC 성능, 근무 위치의 한계로 AI Agent 개발이 어려웠다.

2. 원인 — 근무 위치로 인하여 동일한 PC사용의 어려움과 업무 환경에서 LLM 사용 제약이 있었고, 로컬 자원만으로는 개발·테스트가 비효율적이었다.

3. 해결 방법 — GitHub(코드관리), Pinecone(벡터DB), Render(서비스배포)를 활용한 완전한 클라우드 기반 개발·배포 환경으로 전환했다.

4. 결과 — 장소와 장비 의존도를 줄이고 일관된 개발·운영 파이프라인을 구축했고, 오히려 배포 자동화 측면에서 더 효율적인 환경을 확보했다.

### 저신뢰 검색 결과 처리

1. 문제 상황 — 일부 품목은 RAG 검색 유사도가 낮아 근거 기반 추천이 어려웠다.

2. 원인 — 적재 문서에 없는 품목이거나 검색 근거가 충분하지 않은 경우가 발생했다.

3. 해결 방법 — 유사도 임계값(similarity threshold)을 두고 임계값 미달 시 fallback=True로 분기하도록 설계했다.

4. 결과 — 근거 없는 확정형 답변을 줄이고 참고용 응답과 경고를 함께 제공할 수 있게 됐다.

### 구현 증빙 및 테스트 문서화 한계

1. 문제 상황 — 테스트와 고도화 단계의 실행 기록이 충분히 문서화되지 않았다.

2. 원인 — 구현 설명 중심으로 정리되어 시나리오별 실제 결과와 전후 비교가 부족했다.

3. 해결 방법 — 향후 테스트 시나리오 표, 성공 기준, 개선 전후 수치를 분리해 기록하는 방향이 제시되었다.

4. 결과 — 문제 인식은 명확하지만, 최종 보고서에는 추가 보완이 필요한 상태다.

### 벡터 데이터 중복 발

1. 문제 상황 — 정상 벡터 수는 약 6,000개인데, 실제로는 21,301개가 쌓여 있었.

2. 원인 — 문서 적재 기능이 기존 데이터를 삭제하지 않고 계속 추가만 하여, 버튼을 여러 번 클릭할수록 중복 데이터가 누적됐다.

3. 해결 방법 — 적재 전 기존 벡터를 전체 삭제하는 단계를 추가해 항상 최신 데이터만 유지했다.

4. 결과 — 중복 제거로 검색 정확도 개선, 정상 벡터 수 유지할 수 있게 됐다.



# 향후 개선 및 확장 방향

## 단기 개선 (1~3개월)

* Clarification 2턴 대화 루프 구현\
  - 충돌 감지 시 에이전트가 추가 질문 → 사용자 답변 → 단일 코드로 수렴으로 분류 정확도 향상

* Streamlit 스트리밍 응답 적용으로 체감 응답 시간 개선\
  - 답변을 완성 후 한 번에 표시하는 방식 → 글자가 생성되는 대로 실시간 표시를 통한 체감 응답 시간 단

* 정량 평가셋 구축 및 Top-1/Top-3 자동 평가 스크립트 작성

응답 품질과 KPI 측정 가능성이 동시에 높아질 것으로 기대된다.

## 장기 확장 (6개월+)

* **로그 기반 자동 튜닝** — 쌓인 감사 로그에서 오분류 케이스를 추출해 문서 보강 및 프롬프트 개선 자동화

* **사내 시스템 연동** — SAP 자재 마스터, 기존 통관 시스템과 연동해 코드 자동 입력

* **도메인 확장** — 반도체 외 디스플레이, 배터리 등 하이테크 품목으로 적용 범위 확대

실무 적용 범위를 넓히고 조직 단위의 무역 관리 자동화 플랫폼으로 발전시킬 수 있다.
