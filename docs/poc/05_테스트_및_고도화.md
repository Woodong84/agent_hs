# 5. 테스트 및 고도화

## 테스트 목적

RAG 기반 HS-Code 추천 에이전트가 반도체 품목에 대해 **정확한 코드를 근거와 함께 추천**하는지 검증합니다. 또한 문서 미매칭·코드 충돌·도메인 외 품목 입력 등 예외 상황에서 가드레일이 의도대로 동작하는지 확인합니다.

## 2. 품질 평가 — 케이스 유형별 구분

### (1) 정상 추천 케이스 — SC-001 (FOUP)

- **입력:** 품목명 FOUP / 재질 폴리카보네이트 / 용도 300mm 웨이퍼 클린룸 이송 / 수출(미국)
- **결과:** Top-1 3923100000, 근거 품질 6.0/8.0점, Fallback 아니오
- **근거 인용:** `hs_3923_FOUP.txt` p.1 — "플라스틱제 운반용 케이스로서 특정 물품 운반 전용으로 제작된 것은 3923호에 분류"
- **세율:** 기본관세율 8% / 한-미 FTA 0%
- **판정:** 성공 — 정답 코드가 Top-1 출력, 근거 문서 인용 정상

### (2) 문서 미매칭 케이스 — SC-F01 (양자컴퓨터 희석냉동기)

- **입력:** 양자컴퓨터 희석냉동기 / 알루미늄·구리 / 큐비트 냉각 / 수출
- **결과:** 최고 유사도 0.18 < 임계값 0.30 → `fallback=True`
- **UI 출력:** 황색 경고 배너 "⚠️ RAG 문서 근거 없음 — LLM 지식 기반 추천. 반드시 전문가 확인 필요"
- **Fallback 원인 코드:** `유사도 0.18 < 임계값 0.30` 화면 노출
- **판정:** 성공 — 가드레일 정상 동작, 근거 없는 추천을 정상 결과로 오인하지 않도록 차단

### (3) 근거 충돌 케이스 — SC-002 (CMP Slurry)

- **입력:** CMP Slurry / 실리카 수분산액 / 웨이퍼 연마 / 수입(중국) / 기존코드 3824.99
- **결과:** conflict_flag=True, TYPE-2 (기존코드 38류 ↔ 추천코드 38류 → 10단위 불일치)
- **UI 출력:** 주황 경고 배너 + A/B 비교표 + "사내 코드 통일 검토 필요" 메시지
- **추천:** 3810100000 (혼합 연마 조제품, 38류), 기본관세율 6.5% / 한-중 FTA 확인 필요
- **판정:** 성공 — 충돌 감지 및 비교 출력 정상

### (4) 추가 질문 필요 케이스 (Clarification) — SC-003 (세라믹 엣지 링)

- **입력:** 웨이퍼 엣지 링 / Al₂O₃ 세라믹 / 플라즈마 식각 내 웨이퍼 보호 / 수입 / 기존코드 7616999090
- **결과:** 재질(세라믹) 기준 → 6909190000 추천, 기존코드(76류 알루미늄) 와 불일치 → TYPE-2 감지
- **에이전트 동작:** "이 제품의 물리적 형태를 알려주세요 (A: 단일 성분 / B: 혼합물 / C: 불확실)" 추가 질문 출력
- **UI 출력:** A/B 비교표 — 후보A 7616999090(알루미늄 기준) vs 후보B 6909190000(세라믹 기준) + 세율 차이 표시
- **판정:** 성공 — 재질 변경에 따른 류 전환 정상 감지

## 3. 주요 문제 해결 및 기술 리서치

### 이슈 1 — 품질/환각

**(1) 문제 상황 및 원인**

SC-001(FOUP) 테스트에서 기대 Top-1(`3923100000`) 대신 STOCKER(`8486403010`)가 출력됨.
원인: 232개 HS 표준 해석 지침 문서가 Pinecone에 대량 적재되어 FOUP 특화 문서가 희석됨. STOCKER 문서의 "웨이퍼 이송·보관" 키워드가 FOUP 쿼리와 코사인 유사도에서 오매칭. 신뢰도도 항상 "낮음"으로 표시됨 — `_score_to_confidence()` 기준값(0.85/0.75)이 Pinecone 코사인 유사도 실측 범위(0.37~0.55)와 괴리.

**(2) 리서치 및 해결 과정**

- **리서치:** Dense Vector 검색의 Nearest Neighbor 특성 분석 — 유사도 임계값이 품질 관문 역할을 함을 확인. 쿼리 시점 가중치 부여(Query-time Weighting) 방법으로 텍스트 반복, 메타데이터 필터, 별도 임베딩 필드 3가지 방법 검토.
- **해결 과정:**

| 변경 항목 | 변경 전 | 변경 후 |
|---|---|---|
| RAG 쿼리 구성 | `"{품목명} {재질} {용도} {수출입}"` | `"{품목명} {품목명} {재질} {용도} {수출입}"` (품목명 2회 반복) |
| FOUP 문서 규모 | 기본 설명 27줄 | 영문명·유사품목·관련 키워드 포함 47줄로 확장 |
| 신뢰도 기준값 | 높음≥0.85 / 중간≥0.75 | 높음≥0.60 / 중간≥0.45 (INVARIANT-04) |
| UNKNOWN 후보 노출 | hs_code 없는 청크도 후보 목록 포함 | hs_code 없는 청크는 후보에서 제외 |

---

### 이슈 2 — 속도/지연

**(1) 문제 상황 및 원인**

응답 시간 최대 25초 소요. ReAct 루프 구조상 `search_hs_code_rag → query_tax_rate` 순차 호출마다 LLM API 왕복이 발생하고, Pinecone 연결·임베딩 모델 로드가 매 요청마다 재실행(콜드 스타트).

**(2) 리서치 및 해결 과정**

- **리서치:** LangChain AgentExecutor 도구 순차 호출 구조 분석 — ReAct 방식은 Thought→Action→Observation 1사이클에 LLM 호출 1회 필수. Render 무료 플랜 서버(미국) ↔ Azure OpenAI 엔드포인트 간 네트워크 지연도 확인.
- **해결 과정:**

| 변경 항목 | 변경 전 | 변경 후 |
|---|---|---|
| Pinecone 연결 | 매 요청마다 신규 연결 | `_vectorstore` 전역 싱글톤 캐싱 |
| 임베딩 모델 로드 | 매 요청마다 재초기화 | `_embeddings` 전역 싱글톤 캐싱 |
| 벡터 중복 누적 | 적재 시 기존 벡터 삭제 없음 (21,301개 비정상) | `delete_all=True` 후 재적재 (정상 수량 유지) |
| 응답 시간 | 최대 25초 | 2회차 요청부터 7~11초 수준 |

> **남은 한계:** 첫 번째 요청은 여전히 콜드 스타트 발생. LLM 3회 왕복 구조는 유지 중. E2E 단계에서 스트리밍 응답(`st.write_stream`) 및 병렬 도구 호출 도입으로 체감 지연 추가 개선 예정.

### 이슈 3 — 보안/가드레일

**(1) 문제 상황 및 원인**

두 가지 구조적 취약점 발견:
- **감사 로그 공백:** `save_audit_log`를 LLM 도구 목록에 포함시켰을 때 `input_data` 필드가 항상 빈 `{}`로 기록. LLM이 도구 호출 시 초기 입력값을 컨텍스트에서 참조하지 못하는 ReAct 구조적 특성에 기인.
- **Fallback 오인 위험:** Fallback 상태에서도 구체적인 HS-Code 번호가 포함된 정상 결과처럼 보이는 답변이 출력되어, 사용자가 근거 없는 추천을 신뢰할 위험 존재.

**(2) 리서치 및 해결 과정**

- **리서치:** AI 출력 투명성(Transparency) 설계 원칙 — 결과의 신뢰 수준을 사용자에게 명시적으로 표시해야 한다는 LLM 가이드라인 확인. OWASP LLM Top 10의 LLM02(부적절한 출력 처리) 항목에서 규제 도메인 출력은 코드 레벨에서 강제해야 함을 확인.
- **해결 과정:**

| 변경 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 감사 로그 저장 방식 | LLM 도구 목록(`_TOOLS`)에 포함 | `_TOOLS`에서 제거, `run_agent()` 내부 직접 `invoke()` 호출 (INVARIANT-01) |
| Fallback UI 표시 | 일반 텍스트로 결과 출력 | 황색 경고 배너 + Fallback 원인 코드(`유사도 X.XX < 임계값 Y.YY`) 노출 |
| 면책 문구 | LLM 프롬프트에만 명시 | 모든 응답 말미 하드코딩 고정 출력 (INVARIANT-07) |
| 임계값 하한선 | 코드 내 제한 없음 | `similarity_threshold` 최소 0.30 강제 (INVARIANT-02) |
| 충돌 감지 | 미구현 | TYPE-1/2/3 자동 분류, 주황 경고 배너 + A/B 비교표 출력 |
| 감사 로그 필드 | input, output 기본 필드 | `resolution.expert_referral`, `resolution.clarification_turns` 추가 |

**가드레일 실제 동작 확인 사례:**
- 도메인 외 품목(양자컴퓨터 희석냉동기) 입력 시 → 유사도 0.18 감지 → Fallback 황색 배너 + "LLM 지식 기반 추천, 전문가 확인 필수" 경고 정상 출력
- `save_audit_log` 직접 호출 전환 후 → `input_data` 필드에 품목명·재질·용도 전체 정상 기록 확인

## 6. 남은 한계 및 E2E 단계 계획

|---|---|---|

| 참조 문서 범위 | 246개 문서, 반도체 주요 류 중심 | HS 해설서 28·38·39·84·85류 전체 섹션 추가 적재 |
